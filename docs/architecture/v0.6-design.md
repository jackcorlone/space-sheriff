# Space Sheriff v0.6 定时只读扫描设计

状态：Accepted  
目标版本：v0.6.0  
基线版本：v0.5.0

## 1. 背景与决策

v0.5 已具备本地索引、重复文件检测、版本化策略和审计能力，但扫描仍依赖用户打开界面。
v0.6 引入由操作系统触发的定时扫描，让磁盘变化可以被持续发现，同时保持产品最重要的安全边界：
后台任务只读取元数据、计算哈希、更新本地索引和生成报告，绝不移动或删除文件。

本版本选择操作系统原生计划任务，而不是常驻守护进程：

- macOS 使用当前用户的 LaunchAgent 和 `StartCalendarInterval`。
- Windows 使用当前用户的 Task Scheduler（`schtasks.exe`）。
- 同一个可执行文件通过 `--scheduled-scan <id>` 进入无界面单次运行模式。

这比常驻服务更容易审计、卸载和限制权限，也不需要管理员权限。

## 2. 目标与非目标

### 目标

- 保存每日或每周扫描计划及其完整扫描参数。
- 注册、更新和移除当前用户的操作系统计划任务。
- 提供不启动浏览器或 HTTP 服务的单次扫描模式。
- 使用 SQLite 租约阻止同一计划并发运行，并允许崩溃后的过期租约恢复。
- 保存定时扫描会话、统计和有限数量的高占用文件结果。
- 在界面中创建、启停、立即运行计划，并查看最近运行历史。
- 注册失败时保留计划和错误状态，允许用户修正后重试。

### 非目标

- 不自动清理、自动加入清理计划或自动批准建议。
- 不建立常驻 daemon、Windows Service 或系统级任务。
- 不请求管理员权限，不扫描当前用户原本无权访问的目录。
- 不在定时扫描结束后弹窗或上传数据。
- 不恢复整个历史目录树；历史只保存摘要和结果上限内的文件。
- 不处理机器休眠后的精确补偿调度，触发语义由操作系统负责。

## 3. 用户流程

1. 用户在“定时扫描”中选择名称、目录、每日/每周时间和扫描阈值。
2. 应用先保存期望配置，再调用当前平台的任务注册器。
3. 注册成功显示“已注册”；失败显示“注册失败”和有限长度错误，可再次保存重试。
4. 系统到时启动同一可执行文件的无界面模式。
5. 无界面进程读取计划、获取租约、执行只读扫描、保存结果并退出。
6. 用户下次打开界面可查看状态、耗时、文件数、错误数和高占用文件。

关闭计划会移除系统任务但保留计划与历史；删除计划会先尝试移除系统任务，再删除计划。

## 4. 数据模型：SQLite schema v3

### `scan_schedules`

| 字段 | 含义 |
| --- | --- |
| `id` / `name` | 随机 ID 与 1–80 字符名称 |
| `root` | 规范化后的现存目录绝对路径 |
| `cadence` | `daily` 或 `weekly` |
| `hour` / `minute` / `weekday` | 本地时间；每周使用 0–6（周日到周六） |
| `minimum_bytes` | 大文件结果阈值 |
| `duplicate_minimum_bytes` | 重复文件哈希阈值，至少 1 MiB |
| `result_limit` | 保存结果上限，1–2,000 |
| `excludes_json` | 最多 100 条排除规则的规范 JSON |
| `enabled` | 用户期望计划是否启用 |
| `backend_state` / `backend_error` | `disabled`、`registered` 或 `error` 及错误摘要 |
| `created_at` / `updated_at` / `last_run_at` | Unix 纳秒时间 |

### `scan_sessions` 扩展

增加 `schedule_id`、`trigger`、`policy_id` 和 `policy_version`。`trigger` 为
`interactive`、`scheduled` 或 `manual_schedule`。会话固化运行时策略，避免之后切换策略造成历史歧义。

### `scan_findings`

按会话保存结果上限内的路径、大小、修改时间和建议快照。外键随 90 天会话保留策略级联删除。
定时扫描不会把这些结果写入清理计划。

### `schedule_leases`

每个计划最多一条租约，包含 owner 和获取时间。获取租约时在事务内删除超过 6 小时的旧租约后插入；
正常退出时删除。它只负责互斥，不代表任务成功。

## 5. 运行模型

```text
OS scheduler
    │  executable --scheduled-scan <id> --data-dir <dir>
    ▼
open SQLite ──► load enabled schedule ──► acquire lease
    │                                      │
    └── failure: non-zero exit             └── busy: exit code 3
                                               │
                                               ▼
                                      synchronous read-only scan
                                               │
                                               ▼
                                     persist session + findings
                                               │
                                               ▼
                                         release lease + exit
```

无界面模式不监听端口、不打开浏览器。扫描目标文件只通过 `WalkDir`、`Lstat` 和只读哈希打开；
数据库和日志目录是唯一写入位置。

## 6. 平台注册

### macOS

- 文件：`~/Library/LaunchAgents/com.spacesheriff.scan.<id>.plist`
- `ProgramArguments` 使用参数数组，避免 shell 解释。
- 使用 `StartCalendarInterval` 表达小时、分钟和可选 Weekday。
- 标准输出和错误写入 Space Sheriff 数据目录的 `logs` 子目录。
- 更新时先 `launchctl bootout`（未加载可忽略），再原子写入 plist 并 `bootstrap gui/<uid>`。

当前便携二进制采用 LaunchAgent。未来签名 `.app` 分发应迁移至 Apple ServiceManagement/SMAppService，
由应用声明和管理登录项。

### Windows

- 任务名：`SpaceSheriff-<id>`
- `schtasks /Create /SC DAILY|WEEKLY /ST HH:mm /TN ... /TR ... /F`
- 每周计划增加 `/D SUN|MON|...|SAT`。
- 使用当前用户上下文和有限权限；不注册 SYSTEM 任务。
- 禁用或删除使用 `schtasks /Delete /TN ... /F`。

路径参数由平台专用引用函数编码，不经过 PowerShell 或 `cmd /c`。

## 7. API

- `GET /api/schedules`：计划、平台能力和最近运行摘要。
- `POST /api/schedules/save`：创建或更新计划；保存后协调系统注册状态。
- `POST /api/schedules/toggle`：启用或停用计划。
- `POST /api/schedules/run`：在当前应用进程中立即执行一次，只允许一个活动扫描。
- `POST /api/schedules/delete`：移除系统任务并删除计划。
- `GET /api/scheduled-scans?limit=20`：最近定时/手动计划扫描摘要。
- `GET /api/scheduled-scans?id=<session-id>`：一次运行的有限结果详情。

所有接口继续受回环监听、Host 校验、随机会话令牌、JSON 内容类型和请求大小限制保护。

## 8. 失败、一致性与恢复

- 数据库是期望状态的权威来源，系统任务是可重建的派生状态。
- 保存成功但注册失败时，计划保留 `enabled=1`、`backend_state=error`，界面明确提示。
- 更新计划先保存数据库再重新注册；旧系统任务移除失败会阻止覆盖并记录错误。
- 无效、禁用或不存在的计划不能从命令行执行。
- 计划根目录在执行时不存在，生成失败会话，不自动改写计划。
- 进程崩溃后，超过 6 小时仍未完成的会话由启动恢复逻辑标记失败；较新的会话可能属于另一个
  正在运行的前台或定时进程，不得被新进程改写。超过 6 小时的租约可被新运行接管。
- 应用卸载前用户应先删除计划；遗留任务启动不到可执行文件时由系统记录失败，不造成文件修改。

## 9. 安全与隐私

| 风险 | 控制 |
| --- | --- |
| 后台误删 | 无界面路径不链接任何清理调用；定时 API 不接受删除动作 |
| 参数或 shell 注入 | 固定参数数组、ID 白名单、平台引用函数、无 shell |
| 并发扫描占满磁盘 | SQLite 租约 + 前台进程单任务锁 |
| 任意目录扫描 | 目录必须在保存和执行时存在，权限继承当前用户 |
| 历史泄露文件内容 | 仅保存路径、大小、时间、哈希索引和建议，不保存内容 |
| 注册失败被隐藏 | 持久化 backend 状态和错误，界面可见 |
| 计划修改后历史含义改变 | 每个 session 固化 root、trigger 和策略版本 |

拥有当前账户权限的其他进程仍可修改数据库或系统任务；v0.6 不提供账户内防篡改保证。

## 10. 验收标准

1. 新库与真实 v2 fixture 可迁移到 v3；高版本库继续安全拒绝。
2. 计划字段、时间、阈值、结果上限和排除规则的非法输入均被拒绝。
3. macOS plist 和 Windows `schtasks` 参数有确定性单元测试，路径含空格时仍正确。
4. 创建、更新、停用、删除在模拟注册器下正确维护 backend 状态。
5. `--scheduled-scan` 不启动 HTTP/浏览器，成功后保存 session 和 findings。
6. 禁用/不存在计划及重复租约不能运行；过期租约可恢复。
7. 后台运行不调用清理、回收站或清理计划写入。
8. UI 可管理计划、立即运行并查看最近历史，首次加载无控制台错误。
9. `go test -race ./...`、覆盖率门槛、`go vet`、前端语法检查及四平台无 CGO 构建全部通过。

## 11. 后续边界

v0.7 可处理签名安装包、SMAppService、Windows 安装器、签名更新清单和任务自修复。
企业集中策略、远程审计和多设备管理需要服务端身份与密钥体系，应作为独立版本设计。
