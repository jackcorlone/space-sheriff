# Space Sheriff v0.9 可解释报告与新手引导设计

状态：Prototype implemented
目标版本：v0.9.0
基线版本：v0.8.0

## 1. 背景与范围

v0.8 已经可以在本机扫描、检测重复文件、保存清理计划并导出结果，但普通用户仍需要自己理解
CSV/JSON 字段。扫描质量面板也只能告诉用户有多少错误或排除项，不能把“下一步该做什么”说清楚。

v0.9 的原型把重点放在可解释性：让用户先看懂报告，再决定是否需要清理。它不改变后台只读和
“清理必须由用户明确发起”的安全边界，也不引入云端服务。

## 2. 目标与非目标

### 目标

- 为扫描结果增加固定的“位置 → 大小 → 时间 → 原因 → 重复 → 动作”判断路径；
- 在界面显示新手分析指南，根据当前扫描状态给出有限、可执行的下一步；
- JSON 导出包含扫描摘要、预算/错误/排除计数和引导建议；
- CSV 导出提供人类可读大小和下一步动作，便于在 Excel/Numbers 中筛选；
- 导出文件明确说明它是本次扫描快照，不会上传到云端。

### 非目标

- 不根据规则自动删除文件，不自动清空回收站；
- 不把建议分数伪装成确定性结论；
- 不在 v0.9 原型中上传文件内容、路径或报告；
- 不把 JSON 导入作为恢复清理计划的入口；
- 暂不保存逐条权限错误的原始路径，避免把敏感路径写入额外报告。错误类别样本列入 v0.9.1。

## 3. 用户工作流

```text
选择用户目录
  → 扫描完成
  → 先看读取错误/规则排除
  → 按大小和建议筛选
  → 阅读 reason 与 nextStep
  → 检查 duplicateGroup，保留一个副本
  → 手动加入清理计划
  → 再次确认后移入系统回收站
```

指南面板只提供提示，不替代用户确认。扫描 `/` 时出现权限错误，指南建议先改为扫描当前用户目录；
资源预算耗尽时，指南建议提高预算或拆分目录；规则排除只提示“它们不是错误”。

## 4. 导出数据契约

### JSON

JSON 顶层增加 `summary`：

```json
{
  "state": "done",
  "root": "/Users/me",
  "filesSeen": 1234,
  "bytesSeen": 987654321,
  "errors": 0,
  "excluded": 56,
  "filesFingerprinted": 120,
  "filesHashed": 80,
  "hashesReused": 40,
  "budgetBytes": 0,
  "budgetDurationMs": 0,
  "budgetExceeded": "",
  "resultCount": 20,
  "duplicateGroupCount": 2,
  "plannedCount": 0,
  "guidance": [
    {"title": "先看建议标签", "action": "优先复核大文件结果中的 reason 和 nextStep。"}
  ]
}
```

每个 `files` 行增加：

- `sizeHuman`：例如 `5.0 GB`，避免普通用户直接换算字节；
- `nextStep`：基于受保护、个人文件、缓存、安装包、压缩包等规则给出的动作提示；
- 原有 `path`、`size`、`modifiedAt`、`advice`、`category`、`ruleId`、`reason`、`duplicateGroup` 保持兼容。

### CSV

列顺序为：

```text
path,size,sizeHuman,modifiedAt,advice,category,ruleId,reason,nextStep,duplicateGroup
```

CSV 适合排序和筛选；读取错误、规则排除和预算等扫描级信息以 JSON `summary` 为准，避免把同一份
摘要重复到每一行。

## 5. 界面原型

- “扫描概览”下增加“新手分析指南”卡片；无扫描时显示固定四步，扫描后根据状态调整优先事项；
- 大文件导出按钮下显示“CSV 适合表格筛选，JSON 包含扫描摘要；文件保存到浏览器下载文件夹”；
- JSON 导出成功提示文件名，CSV 导出成功提示文件名；
- 既有扫描质量面板继续区分读取错误、规则排除和资源预算，不隐藏原始计数。

## 6. 安全与隐私

- 所有导出在浏览器内由当前扫描结果生成，不经过远程 API；
- 导出不包含文件内容，只包含路径、元数据、规则建议和重复组标识；
- 系统/应用目录仍不能加入清理计划，旧扫描记录也不能绕过清理入口；
- `nextStep` 是解释性提示，最终操作仍经过现有文件类型、大小、修改时间和系统路径复核。

## 7. 验收标准

1. 未扫描时指南显示选择位置、扫描、阅读建议、再决定四步；
2. 有读取错误时指南首先建议缩小扫描范围，并明确排除项不是错误；
3. 预算耗尽时指南显示提高预算或拆分目录，不显示“扫描失败”；
4. JSON 有 `summary` 且包含状态、错误、排除、预算、结果数量和指南；
5. CSV 含 `sizeHuman` 和 `nextStep`，旧字段仍存在；
6. 导出仍为本地浏览器下载，无网络上传；
7. `go test -race ./...`、`go vet ./...`、前端语法检查、Python 测试和本地 HTTP 页面冒烟通过。
