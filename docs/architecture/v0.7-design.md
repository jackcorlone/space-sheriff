# Space Sheriff v0.7 计划可靠性设计

状态：Implemented
目标版本：v0.7.0
基线版本：v0.6.0

## 1. 目标

v0.7 不改变后台只读边界，也不增加数据库 schema 版本。它把已有的计划配置、扫描历史和系统任务注册器
组合成可解释的运行状态：

- 显示每日/每周计划的预计下次运行时间；
- 显示最近一次计划扫描状态和失败原因；
- 发现自上次有效配置或成功运行后已经过去的计划运行次数；
- 检查系统任务是否缺失、被修改或处于未知状态；
- 允许用户通过一个“修复任务”动作重新同步系统任务。

## 2. 状态计算

`GET /api/schedules` 在返回前为每个计划计算以下只读字段：

| 字段 | 含义 |
| --- | --- |
| `nextRunAt` | 按本地时区计算的下一次每日/每周触发时间，Unix 纳秒 |
| `missedRuns` | 自 `max(created_at, updated_at, last_run_at)` 后已到期但没有运行记录的次数 |
| `lastRunState` / `lastRunMessage` | 最近一次 `scheduled` 或 `manual_schedule` 会话快照 |
| `driftState` | `ok`、`missing`、`drifted` 或 `unknown` |
| `driftMessage` | 平台检查的可读原因 |

时间计算使用 `time.Local`，星期沿用 v0.6 的 0–6（周日到周六）约定。计划停用时不计算下次运行和错过次数。
配置更新或重新启用会把 `updated_at` 作为新的错过计数起点，避免把停用期间误报为错过。

## 3. 平台检查

平台注册器通过可选的 `scheduleInspector` 能力提供检查，不影响旧的模拟注册器：

### macOS

1. 检查 `~/Library/LaunchAgents/com.spacesheriff.scan.<id>.plist` 是否存在；
2. 启用计划时将文件内容与当前期望的参数数组、日历和路径逐字节比较；
3. 使用 `launchctl print gui/<uid>/com.spacesheriff.scan.<id>` 确认服务已加载；
4. 停用计划若仍有 plist，报告漂移；没有文件则正常。

### Windows

1. 使用 `schtasks.exe /Query /TN SpaceSheriff-<id> /XML` 查询任务；
2. 区分任务不存在、查询错误和任务存在但已停用；
3. 对可执行文件、数据目录和计划 ID 做不区分大小写的参数核对；
4. 任务缺失或参数不一致时报告漂移。

平台检查是只读操作，不会自动修改任务。`POST /api/schedules/repair` 才会调用现有的 Install/Remove
流程重新同步。

## 4. 失败提醒

计划状态响应新增 `alerts` 数组。以下情况会生成本地界面提醒：

- 最近一次计划扫描为 `failed`；
- 已错过至少一次计划运行；
- 系统注册状态为 `error`；
- 系统任务 `missing`、`drifted` 或 `unknown`。

提醒只显示在本地 Web 界面，不弹出系统通知、不联网、不修改文件。计划卡片同时展示预计下次运行、最近状态、
错过次数和修复按钮。

## 5. API

- `GET /api/schedules`：新增状态字段和 `alerts`。
- `POST /api/schedules/repair`：接受 `{ "id": "..." }`，重新安装启用计划或移除停用计划，返回完整状态。

该接口与其他计划接口一样受回环监听、Host、会话令牌、JSON 内容类型和请求大小限制保护。

## 6. 生命周期与清理语义

- `POST /api/quit` 取消活动扫描，等待其完成报告落库或最多等待 5 秒，再执行 `http.Server.Shutdown`；
  主流程随后正常返回并关闭 SQLite。
- 计划会话恢复会检查新鲜的 `schedule_leases`，不会因为扫描已经运行超过 6 小时而误报中断。
- 前台扫描请求区分缺省参数与显式参数；显式非法阈值和结果上限返回 400。
- 清理响应新增 `movedBytes`，表示移入回收站的逻辑大小；旧 `released`/`releasedBytes` 字段仅为兼容别名，
  不代表当场增加的磁盘可用空间。

## 7. 一致性与安全

- 状态计算不改变数据库；只有计划历史查询和平台只读检查会发生。
- 修复操作仍以数据库中的期望配置为准，注册失败会保留 `backend_state=error` 和错误信息。
- 后台 `--scheduled-scan` 不读取或调用修复接口，仍然只扫描、哈希和保存报告。
- 预计时间和错过次数不是操作系统的保证；机器休眠、关机、权限和平台调度策略可能导致实际触发不同。
- v0.7 仍不提供系统通知、补偿式重试或自动清理。

## 8. 验收标准

1. 每日计划在触发时间前显示当天时间，触发时间后显示下一天；每周计划正确跨周计算。
2. 没有运行记录且计划已跨过触发时间时显示错过次数；停用期间不累计。
3. 最近失败会在计划卡片和 `alerts` 中显示失败原因。
4. 模拟平台可返回缺失/漂移，修复接口会再次调用 Install/Remove 并刷新状态。
5. macOS arm64/amd64、Windows amd64/arm64 无 CGO 构建通过，race、vet、前端语法和现有测试通过。
6. v0.6 schema v3 数据库无需迁移即可读取新增状态。
