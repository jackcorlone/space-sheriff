# Space Sheriff v0.8 百万文件与慢盘设计

状态：Implemented (development build)
目标版本：v0.8.0
基线版本：v0.7.0

## 1. 背景与范围

v0.7 已经解决计划任务的可观察性和生命周期问题，但扫描器仍把所有重复候选、按大小分组和完整哈希中间结果留在进程内。
在百万文件、外置慢盘或重复阈值很低的目录上，这会放大内存占用、随机 I/O 和取消延迟。

v0.8 只处理扫描流水线和资源边界，不改变“后台只读、清理必须由用户明确发起”的安全边界。

## 2. 目标与非目标

### 目标

- 将带索引扫描的重复候选下沉到 SQLite，按本次扫描会话的文件尺寸逐组读取；不再在扫描阶段保留全量候选数组。
- 对同尺寸文件先读取首尾最多 64 KiB 的快速指纹，只有快速指纹相同的文件才计算完整 SHA-256。
- 完整哈希按最多 256 条一批写入 SQLite；批次使用 `context.Context`，取消时事务整体回滚。
- 为交互式扫描和定时扫描提供可选的逻辑字节上限、最长运行时间上限，并在状态和历史中记录“预算耗尽”。
- 将定时扫描预算持久化到 schema v4，旧 v3 数据库自动迁移且默认预算为 0（不限制）。
- 提供可重复的文件量基准入口，先测量再制定 10 万/100 万文件的发布门槛。

### 非目标

- 不把快速指纹写入数据库；它是一次扫描内的廉价预筛，文件元数据变化仍由现有 SHA-256 缓存规则处理。
- 不承诺固定扫描速度、固定峰值内存或对网络卷的服务等级；这些数值必须由目标硬件基准给出。
- 不在本版本引入并发哈希、I/O 限速器、压缩索引或后台自动清理。
- 不把目录聚合、最终重复组结果和前端展示结果无限制地分页化；它们是下一轮的规模优化项。

## 3. 扫描流水线

```text
WalkDir
  ├─► 小批次写入 files(last_seen_session)
  ├─► 有界 top-N 大文件堆
  └─► 扫描结束
        └─► SQLite: 同尺寸且至少两条记录
              └─► 首尾快速指纹（每个尺寸组）
                    └─► 完整 SHA-256（快速指纹相同）
                          └─► 256 条哈希批量写入
```

索引模式下，`files.last_seen_session` 是本次扫描的边界。相同物理身份只有一条 `files` 记录，因此硬链接不会因为多路径而制造可释放的重复组。
尺寸组逐组处理，最坏情况下仍会暂时保留“单个尺寸组”的记录；这比保留整棵目录的候选集合可控，但极端的同尺寸海量文件仍需后续分页化。

快速指纹把逻辑大小和文件首尾内容放入 SHA-256 输入。文件小于等于 128 KiB 时读取一次完整内容；更大的文件只读取首尾各 64 KiB。
快速指纹失败、文件在扫描期间改变或上下文取消时不会写入完整哈希缓存。

## 4. 资源预算

`ScanOptions` 新增 `MaxBytes` 与 `MaxDuration`。HTTP `POST /api/scan` 对应字段为：

```json
{
  "path": "/data",
  "maxBytes": 10737418240,
  "maxDurationSeconds": 3600
}
```

值为 0 表示不限制；服务端拒绝负值、超过 1 ZiB 的字节预算和超过 7 天的时间预算。`maxBytes` 约束扫描遍历阶段累计发现的逻辑字节，`maxDurationSeconds` 覆盖遍历、指纹和完整哈希的全流程耗时。定时计划使用 `maxBytes` 与 `maxDurationSeconds` 保存相同语义。

达到任一预算后，扫描停止继续遍历，状态为 `budget_exceeded`，并返回 `budgetExceeded` 和 `message`。已经发现的大文件结果保留；重复检测不会在不完整的索引上继续运行。
预算停止不是清理操作，也不会移动文件。计划历史会保存该状态，计划中心将其作为“预算耗尽”提醒展示。

## 5. SQLite schema v4

v4 在 `scan_schedules` 增加：

| 字段 | 含义 |
| --- | --- |
| `max_bytes` | 每次计划扫描允许累计读取的逻辑字节，0 表示不限制 |
| `max_duration_seconds` | 每次计划扫描允许运行的秒数，0 表示不限制 |

迁移仍在单独事务内完成。v3 数据库打开时自动执行 v4；旧计划得到两个 0 默认值。高于 v4 的数据库继续拒绝打开，不尝试降级或静默重建。

## 6. 一致性与故障处理

- 索引批次和哈希批次都在事务中提交；取消发生在批次中间时整批回滚，不留下半批文件记录。
- SQLite 写入失败会累计错误并使扫描进入 `error`，不会把部分索引伪装成成功完成。
- 扫描状态在最终报告中记录文件数、逻辑字节、快速指纹数、完整哈希数、复用数和预算原因。
- 预算停止、用户取消和存储错误是不同状态，便于定时历史和恢复逻辑区分。
- 现有 WAL、`synchronous=FULL`、租约和启动恢复机制保持不变。

## 7. API 与界面

- `POST /api/scan` 接受可选的 `maxBytes`、`maxDurationSeconds`。
- `GET /api/status` 增加 `filesFingerprinted`、`budgetBytes`、`budgetDurationMs` 和 `budgetExceeded`。
- `ScanSchedule` 和计划编辑界面增加同名预算字段；计划卡片显示预算摘要。
- 状态栏显示快速指纹数量；预算停止会明确显示“扫描达到预算”，不会误报普通失败。
- 便携版界面使用内嵌 SVG 图标，不依赖外部 CDN；扫描概览卡片汇总当前状态、扫描文件、重复可回收空间和清理计划。
- “空间画像”用相对条形图比较扫描空间、大文件结果、重复可回收空间和清理计划；“扫描质量”展示快速指纹、完整哈希复用、读取错误、规则排除和预算状态。
- “读取错误”只统计权限受限、文件消失、元数据/哈希读取失败和本地索引写入失败；“规则排除”是按用户配置主动跳过的项目，不是错误；预算为 0 显示为“未设置（不限）”，表示没有资源上限。
- 面板在窄屏下自动折叠为单列，图标标记保留语义文字，确保离线运行和键盘操作不依赖颜色或图片资源。
- 界面不是独立的云端应用：Go 进程在 `127.0.0.1` 提供静态页面和 `/api/*`，页面使用启动时生成的一次性令牌调用本地 API。直接打开 `file://` 只会得到静态预览，前端会显示连接说明并禁用扫描按钮。

## 8. 验收标准

1. 带 SQLite 索引的重复扫描不再创建全量 `duplicateCandidates`；同尺寸不同快速指纹的文件不进入完整哈希阶段。
2. 相同内容文件仍形成完整重复组，第二次扫描可复用完整哈希；硬链接仍不形成重复组。
3. 已取消的索引或哈希批次不产生部分提交；`go test -race ./...` 覆盖该事务边界。
4. 交互式和计划扫描达到字节/时间预算时状态为 `budget_exceeded`，历史和界面展示原因，源文件未被修改。
5. v3 数据库可迁移到 v4；v4 计划预算可保存、读取并用于 `executeSchedule`。
6. `go vet`、前端语法检查、Python 测试、四平台无 CGO 构建和文件量基准命令均可执行。

## 9. 已知缺口与后续

- 当前目录聚合表、最终重复组和单个极端尺寸组仍可能较大；v0.8.1 应加入分页查询和结果上限/背压。
- 快速指纹未持久化，跨次扫描仍需重新读取首尾块；可在后续 schema 中加入可失效的采样摘要。
- 还没有真实磁盘已满、断电、外置盘拔出和 100 万文件的跨平台实机证据；发布前必须补齐并记录峰值 RSS、数据库增长、取消延迟和错误样本。
- 文件哈希前后元数据复核、错误类别样本和网络卷策略仍是后续可靠性工作。
