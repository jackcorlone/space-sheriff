# Space Sheriff v1.0 稳定版设计

目标版本：1.0.0
状态：本地实现与自动化验证完成；签名分发、真实系统任务和断电场景仍是发布前外部验收门槛。
日期：2026-08-04

## 1. v1.0 的定义

v1.0 不是把所有平台差异隐藏起来，而是冻结一套可以长期兼容、可以诊断、可以回归的本地产品契约：

- 扫描、索引、报告和清理计划都在本机完成，不上传云端；
- 扫描与定时任务始终只读，任何移入回收站的动作都必须由用户在界面中确认；
- SQLite schema v4 作为稳定版数据库格式，v3 数据库可向前迁移，更新版本不会静默降级或覆盖未知版本；
- CLI、HTTP API、导出字段和状态枚举有明确的稳定边界；
- 读取错误不仅有总数，还有有限的分类计数和样本，便于普通用户定位问题；
- Web 界面提供键盘跳转、可见焦点和减少动态效果选项，作为无障碍基线。

## 2. 产品边界与安全不变量

### 2.1 本地边界

应用 HTTP 服务只绑定 `127.0.0.1`，每个进程生成会话令牌；请求必须同时满足本机来源和令牌校验。静态 `file://` 页面不会假装已经连接后端，会明确提示用户启动本地引擎。

### 2.2 只读后台

交互式扫描、定时扫描和 `--scheduled-scan` 都只能读取文件、计算指纹/哈希并保存索引或报告。定时任务不会调用清理接口；清理接口只接受当前扫描结果中的安全记录，并保留系统保护路径和符号链接保护。

### 2.3 数据最小化

扫描错误样本最多保留 20 条，类别、路径和消息分别截断到 48、240、240 个 Unicode 字符。样本只在当前进程状态和交互式 JSON 导出中出现，不写入历史会话表；历史计划报告继续只保存聚合错误数，避免把系统路径长期写入数据库。

## 3. 稳定接口契约

### 3.1 CLI

| 参数 | 行为 | 退出约定 |
| --- | --- | --- |
| `--help` / `-h` | 输出用法并退出，不创建数据库或监听端口 | 0 |
| `--version` / `-v` | 输出 `1.0.0` 并退出 | 0 |
| `--data-dir PATH` | 指定本地 SQLite 索引和报告目录 | 启动失败返回非 0 |
| `--scheduled-scan PLAN_ID` | 无界面、只读执行已保存计划 | 成功 0；租约冲突 3 |

未知参数、缺少参数和非法预算必须在启动前报错。`--scheduled-scan` 与 `--data-dir` 可以组合使用。

### 3.2 HTTP API

`GET /api/version` 返回：

```json
{
  "version": "1.0.0",
  "apiVersion": "v1",
  "schemaVersion": 4
}
```

`/api/status` 的状态枚举保持 `idle`、`running`、`done`、`cancelled`、`budget_exceeded`、`error`。v1.0 新增诊断字段：

```json
{
  "errors": 2,
  "errorCounts": {"metadata": 2},
  "errorSamples": [
    {"category": "metadata", "path": "/受限目录/file", "message": "permission denied"}
  ]
}
```

类别包括 `walk`（目录访问）、`metadata`（文件元数据）、`index`（本地索引）、`fingerprint`（快速指纹）和 `hash`（完整哈希）。客户端必须容忍新增类别和缺省字段，不应依赖样本顺序。

### 3.3 导出

JSON 顶层继续包含扫描结果，并增加 `summary.errorCounts`、`summary.errorSamples`、`summary.guidance`。CSV 保持文件级字段：`path,size,sizeHuman,modifiedAt,advice,category,ruleId,reason,nextStep,duplicateGroup`；诊断聚合只放在 JSON，避免重复到每一行。

## 4. 数据库兼容策略

- `PRAGMA user_version = 4` 是 v1.0 支持的最高版本；
- v3 → v4 迁移只增加定时扫描预算字段，采用事务完成，失败自动回滚；
- `user_version > 4` 直接拒绝打开并提示使用匹配版本，不尝试删除字段或降级；
- v1.0 不新增 schema 版本，错误样本保持内存态，从而冻结历史会话和清理审计结构；
- 发布包升级前应备份 `index.db`，卸载时保留用户明确选择保留的本地数据。

## 5. 可访问性与可解释性基线

- 页面提供“跳到扫描概览”跳过链接；
- 键盘焦点使用高对比度 `:focus-visible` 轮廓；
- 扫描状态卡使用 `role="status"` 和 `aria-live="polite"`；
- `prefers-reduced-motion: reduce` 会关闭脉冲、进度条和提示过渡动画；
- 读取错误卡片显示分类计数，并可展开最多 20 条样本；
- 新手指南明确区分“错误”“规则排除”“预算耗尽”，不会把建议伪装成自动决定。

自动化检查只能覆盖静态属性；VoiceOver、Windows Narrator、真实键盘顺序和高对比度主题仍需在双平台人工回归。

## 6. 发布验收矩阵

### 已在当前环境完成

- Go race、vet、build 与 Python 测试；
- macOS/Windows amd64/arm64 无 CGO 构建；
- CLI `--help`/`--version` 和 API 版本契约测试；
- 诊断计数、样本上限与快照深拷贝测试；
- 本地 UI 扫描、JSON/CSV 导出和新手引导黑盒流程；
- `git diff --check`、前端语法和静态图标/ARIA 检查。

### 发布前必须在独立机器完成

1. Windows 11 真实 Task Scheduler 的注册、启停、睡眠唤醒、升级和卸载残留；
2. macOS 签名、公证、SMAppService/LaunchAgent 生命周期与权限提示；
3. 10 万和 100 万文件、慢盘、外置盘拔出、磁盘已满和进程强杀恢复；
4. 安装→升级→降级→卸载的数据库与报告保留矩阵；
5. VoiceOver/Narrator、键盘全流程和高对比度回归；
6. 至少一个完整发布候选周期无 P0/P1，所有 P2 有接受理由或修复版本。

未完成上述外部门槛时，构建只能标记为 `1.0.0-rc` 或内部稳定候选，不应宣称已完成签名发布。

## 7. 后续维护

v1.0.1 优先处理真实平台验收中发现的兼容性和错误样本可读性问题；任何 API 或数据库破坏性变化必须先发布迁移说明并提升主版本，不在补丁版本中静默改变。
